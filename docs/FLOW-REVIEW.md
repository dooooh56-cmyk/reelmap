# 릴스 → 지도 저장 검토

검토일: 2026-10-30. 공개 배포 v6, 커밋 `2885d8c132f45eba70a70274cbcef9e82ab899f4`.

## 수정한 문제

- `연세로5다길 39`처럼 숫자가 포함된 도로명을 잘못 분리해 정확한 식당도 확인 목록으로 보내던 오류를 수정했다.
- 게시물의 지역 근거와 주소가 일치하고 검색 결과가 유일할 때, 상호에 붙은 지점명을 허용한다. 지역 근거가 없거나 주소가 다르면 자동 저장하지 않는다.
- 자동 저장 뒤 추가 저장 버튼을 없애고 지도에서 해당 식당을 보여준다. iOS 본 앱은 저장 후 입력 화면을 닫고 저장 식당을 선택한다.
- 같은 게시물의 추적 파라미터가 달라도 확인 필요 목록을 중복 생성하지 않는다. 저장 성공 시 해당 실패 기록을 해제한다. 일부 식당이 미확정이면 기록을 유지한다.
- 저장소 쓰기가 실패하면 성공 표시나 메모리 변경을 진행하지 않는다.
- 체험 코드가 없으면 요청 전에 설정을 열고, 입력 후 분석을 자동 재개한다. 인증 오류를 게시물 분석 실패로 저장하지 않는다. 코드는 현재 탭의 새로고침 동안 유지한다.
- iOS는 서버 요청 전에 기기에서 공개 본문을 읽어 전달한다. 로그인 쿠키를 사용하지 않으며 실패하면 서버 분석으로 이어진다. 이 경로는 실기기 검증 전이다.
- 서버의 본문 접근 실패는 HTTP 상태·시간 초과·공개 정보 없음 등으로 구분한다.

## 확인한 결과

- 실제 공개 웹에서 `https://www.instagram.com/p/DfE9JS7E_4y/` 링크만 입력했다. 체험 코드 입력 후 자동 재개 → 아저씨네낙지찜 신촌점 확정 → 지도 핀 선택 → 확인 필요 1건에서 0건으로 변경을 확인했다. 추가 본문이나 파일을 넣지 않았다.
- 기존에 저장된 동일 장소는 중복 생성되지 않았다. 새로고침 후 저장 장소 3곳, 확인 필요 0건, 탭의 체험 코드가 유지됐다.
- 별도 실제 Gemini·카카오 요청은 4.877초, auto_save, 510토큰이었다. 웹 요청은 총 604토큰이었다. 이 시간은 단일 관측이며 보장 성능이 아니다.
- 동일 Swift 본문 로더를 macOS에서 실행해 기존 릴스 2개와 위 게시물의 공개 본문을 확보했다. iPhone에서 실행한 결과와 구분한다.
- core / stages / flow 자동 검사, 배포 산출물 검사, Swift 본문 파서 검사, iOS Simulator 대상 SDK 빌드가 통과했다.
- 저장 순서를 의도적으로 잘못 바꾸면 flow 검사가 실패함을 확인한 뒤 복원했다.

## 남은 중요 항목

1. **높음: 임의 릴스의 공개 본문·영상 확보.** 위 게시물은 링크만으로 성공했지만 인스타그램의 접근 제한, 로그인 요구, 본문에 식당 정보가 없는 영상은 추가 본문·캡처·영상이 필요할 수 있다. 모든 릴스의 링크 단독 자동 저장이 완성된 상태는 아니다.
2. **높음: 실제 iPhone 공유 확장 → App Group → 본 앱 지도 연결.** SDK 빌드는 성공했지만 지원되는 프로비저닝으로 실제 인스타 공유 메뉴에서 끝까지 검증해야 한다. 로컬 공유 그룹 서명 실험은 통과하지 못했다.
3. **중간: 실제 영상·음성 식당 추출 정확도.** 본문·이미지 분석 성공과 구분한다. 영상 파일을 사용한 검증이 남아 있다.

단일 식당에 대한 링크 단독 웹 저장은 실제 성공했다. 제품 전체의 완료 판정은 위 중요 항목까지 확인한 후 내려야 한다.
