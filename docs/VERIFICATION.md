## 링크 단독 본문·영상 확보 검증 (항목 3)

2026-10-30, 로컬 Mac에서 서버가 export한 `canonicalInstagram`·`metadata`와 기본 export `fetch(analyze)`를 실제 네트워크로 실행해 확인. 카카오·Gemini 키 없이 본문 확보 단계만 분리해 측정.

- **본문 확보 성공**: 실제 공개 릴스 2건에서 링크만으로 `og:description` 본문을 받았다. `https://www.instagram.com/p/DfE9JS7E_4y/`(아저씨네 낙지찜, 본문 302자), `https://www.instagram.com/reel/DYEfT3nSuJn/`(논베, 446자). 둘 다 HTTP 200, 로그인 페이지 아님, acquisition `state=fetched`, 1회 시도.
- **영상 확보 실패(구조적)**: 위 성공 2건을 포함해 검사한 모든 공개 페이지에서 `og:video` 보안 URL이 없었다. 즉 **링크 단독으로는 영상 파일을 확보할 수 없고**, 영상 자막·음성 분석은 사용자가 첨부한 파일에 의존한다. 서버는 이를 `video=none`으로 바르게 보고한다.
- **임의 릴스 미보장**: 인스타그램은 존재하지 않는 코드(`ZZZZZZZZZZZ`)와 일부 실제 코드(`C8Qh0VqSxkz`)에도 HTTP 200 + 빈 본문을 반환했다. 서버는 이를 `no_public_content`로 분류해 1회 재시도(총 2회) 후 ‘본문·캡처·영상을 추가해 달라’는 경고와 진단 코드·시도 횟수를 남긴다. 즉 **모든 릴스가 링크 단독으로 처리되지는 않는다.**
- **범위 한정**: 위는 로컬 Mac 네트워크 기준이며, 배포 클라우드 IP에서의 인스타 접근 성공은 이 검사로 재확인하지 않았다(기존 기록의 클라우드 직접 접근 실패 주의가 유지됨). 로그인·challenge·429 응답은 재시도하지 않는 분기도 코드상 유지됨을 확인했다.

결론: 링크 단독 **본문** 확보는 공개 본문이 있는 릴스에서 실제로 동작함을 검증했다. 링크 단독 **영상** 확보는 구조적으로 불가하며, 임의 릴스 전체의 자동 처리는 완성 상태가 아니다.


2026-10-30, 한국 시간 기준. 성공한 검사와 미검증 항목을 구분합니다.

## 배포

- 서버 비밀 변수는 소스와 분리해 반영됨. 이후 사용자가 공개 접속을 명시적으로 허용해 public 전환 성공. 로그인 쿠키 없는 HTTP 요청 200 확인.
- 최초 공개 시도는 자동 승인 검토에서 거절됐으나, 이후 사용자 명시 승인 후 공개 전환 완료.
- 분석 API의 체험 코드 보호는 유지함. 공개 화면과 각 기기의 저장 지도는 별개이며, 기기 저장 데이터가 서버에 공개되는 것은 아님.

## 배포 환경 수정

Cloudflare에서 fetch의 redirect:error가 지원되지 않는 것을 실제 브라우저 검증으로 발견. redirect:manual과 상태 검사를 사용하도록 수정함. 인스타 같은 게시물로의 안전한 이동만 제한적으로 허용하고 외부/로그인 이동은 거부. 회귀 검사 포함.

- URL과 함께 전달된 공유 본문도 보존하도록 수정. 공유 확장 실기기 전체 흐름은 미검증.
